# 标准化测试用例模板（人读版）

> 一条用户价值链一份文档；每个步骤与 `.flow.yaml` 的 step id 双向对应。
> 标 ⌗ 的字段为必填。复制本文件到项目的 `cases/` 目录填写。

## 用例头

| 项 | 内容 |
|---|---|
| ⌗ 用例 ID | `链路缩写-序号`，如 `ORD-PAY-01`（稳定不变，缺陷台账引用它） |
| ⌗ 用例标题 | 一句话描述用户价值，如「业务员可完成下单并看到已支付详情」 |
| ⌗ 所属链路 | 下单支付主链路 |
| ⌗ 优先级 | P0 主路径 / P1 重要分支 / P2 异常 |
| ⌗ 角色/视角 | 业务员（中途切换审计员处单独标注） |
| ⌗ 自动化映射 | `flows/order.flow.yaml#create_order` |
| 版本/基线 | v1.2.0 / 种子数据版本 seed-2026-10 |

## 前置条件

1. 环境：`docker compose up` 后健康检查通过，地址 `${BASE_URL}`
2. 账号：业务员 `sales01 / ***`（权限与文档基线一致）
3. 数据：商品 SKU 已上架；无未支付订单残留（唯一键前缀 `RUN_ID=时间戳`）
4. 依赖：支付沙箱返回固定成功回调

## 测试数据

| 数据 | 规格 | 说明 |
|---|---|---|
| 订单样本 | samples/order.json | 正常一单一品 |
| 规模样本 | samples/5w_rows.csv（GBK） | 满态/性能观察用，不用玩具数据 |
| 唯一键 | `SKU-${RUN_ID}` | 保证可重复执行 |

## 操作步骤与三层预期

| # | 操作（接口/页面动作） | ① 契约层预期 | ② 呈现层预期（用户所见） | ③ 落库层预期 | flow step |
|---|---|---|---|---|---|
| 1 | POST /api/orders 下单 | code=0；status=CREATED；orderNo 匹配正则 | — | biz.orders 新建行 | create_order |
| 2 | GET 轮询至 PAID | status=PAID；paid=true | — | 支付流水已写入 | wait_paid |
| 3 | 打开 /orders/{id} | — | 状态标签「已支付」可见；至少 1 行明细；无登录跳转 | — | page_order_detail |
| 4 | 只读 SQL 查审计 | — | — | create_by=业务员；created_at 非空 | db_audit_column |

### 反面路径（预期拒绝）

| # | 操作 | 预期 | 错误判定 |
|---|---|---|---|
| R1 | 业务员访问他人订单 | HTTP 403/404，body code=403xx | 若返回 200 或页面可见 = 越权缺陷 |
| R2 | 未登录访问详情 | HTTP 401，跳转登录页 | 返回业务数据 = 认证缺陷 |
