# 新项目接入清单（目标：≤2 周达到成熟度 L3）

> L1 可运行 → L2 用户视角 → L3 可回归（CI 定时跑、3 轮无 flaky、报告自动归档）

## 第 0 步：准入判断（缺一慎入）

- [ ] 可一条命令起**干净**环境（compose/helm test profile…）并有健康检查端点
- [ ] 有稳定测试账号（至少：管理员、普通业务角色、低权/只读角色）
- [ ] 种子数据与文档基线一致（账号 ID/角色/字典项固定）
- [ ] 核心业务动线可被业务/产品一句话描述并列出来
- [ ] 能接受 10~15 分钟单轮时长；有 CI 或定时执行条件
- [ ] 不适用项已排除：算法正确性/压测/富交互 UI 走专项，不塞进本套件

## 第 1 步：安装与拷贝

- [ ] Python 3.10+ 虚拟环境：`pip install -r kit/requirements.txt`
- [ ] `python -m playwright install chromium`
- [ ] 拷贝模板：`flow.template.yaml → flows/`、`testcase.template.md → cases/`
- [ ] 建 `.env`（照 `.env` 变量约定：BASE_URL、ADMIN_USER、ADMIN_PASS、平台 DSN）
- [ ] 本地跑通自检：`pytest /path/to/tests/test_flow.py -k selfcheck`

## 第 2 步：梳理（拉上产品/业务评审）

- [ ] 用户旅程表：角色 × 核心目标
- [ ] 主链路清单 7~12 条（标注 P0/P1）
- [ ] 每条链路的实体状态机图（含非法迁移）
- [ ] 每条链路的四要素步骤：动作/前置/后置/观察点
- [ ] 空态/满态时序安排；真实规模样本数据（非 3 行玩具数据）
- [ ] 每链路 ≥1 条反面路径（越权/倒挂/非法迁移/坏输入）

## 第 3 步：造数通路（API）

- [ ] 登录 + 令牌捕获 + 鉴权头模板跑通
- [ ] 健康检查、（可选）重置双开关 ALLOW_RESET
- [ ] 全部步骤变量 capture/引用打通；异步任务用 poll 不用 sleep
- [ ] 唯一键前缀（时间戳/随机码），连跑 2 次不撞键
- [ ] 契约断言：code/http_status/字段/枚举/状态迁移

## 第 4 步：用户视角（浏览器）

- [ ] 登录态注入方式核实（localStorage 键结构 / Cookie），与前端实际一致
- [ ] 每页关键观察点都有 DOM 断言（数据文本、状态标签、行数、登录跳转）
- [ ] 选择器优先 data-testid；推动前端给关键元素补 testid
- [ ] 截图归档；敏感元素 mask 打码
- [ ] 空态步骤排在造数之前；满态步骤排在动线之后
- [ ] 关键表加只读 SQL 断言（审计列、关联、副作用）

## 第 5 步：反面与权限

- [ ] 未登录→401、低权角色→403、管理员→200 三态矩阵
- [ ] 预期拒绝以 HTTP 状态码为主断言，兼容空 body，记录为 PASS
- [ ] 坏文件/非法状态迁移/必填缺失至少各 1 例

## 第 6 步：去脆与 CI

- [ ] 连跑 3 轮 flaky 率 <1%；消灭 >2s 的固定等待
- [ ] CI：起环境→健康检查→`pytest test_flow.py`→归档 test-output→重置
- [ ] 失败非零退出码阻断发布；Junit/报告可在 CI 页面查看
- [ ] 首份报告按 report.template.md 发出

## 第 7 步：运营机制

- [ ] 缺陷→断言闭环台账（bug id ↔ flow#step ↔ commit）
- [ ] 每周：清 flaky、补 testid、理基线；每季：重审链路清单与逃逸率
- [ ] 前端改页面/契约改字段 → 同步更新 flow 写入变更清单
